# Dota2 Voice Command Assistant

Голосовой ассистент для Windows, который по русским голосовым командам:
- запускает Steam, Dota 2, Chrome (с Яндекс.Музыкой) и Discord ("Базовый минимум");
- в клиенте Dota 2 доводит до постановки в очередь рейтингового матча с ролями
  ("Начни рейтинговую игру на мидера" и т.п.).

Распознавание речи — офлайн (Vosk), клики по игровому UI Dota 2 — через
компьютерное зрение (OpenCV template matching), т.к. Panorama UI не отдаёт
accessibility-хендлы стандартным способом.

## 1. Стек технологий

| Задача                          | Выбор                        | Почему |
|----------------------------------|-------------------------------|--------|
| Распознавание речи (RU, офлайн)  | **Vosk** (`vosk-model-small-ru`) | Работает без интернета и без ключей API, низкая задержка, готовая маленькая русская модель. `faster-whisper` точнее, но тяжелее по CPU/задержке для реалтайм-прослушивания в фоне — оставлено как возможная замена (см. `src/dota_voice/speech.py`). |
| Аудиовход                        | `sounddevice`                 | Простой стрим PCM-фреймов, отдаёт `int16`, который Vosk понимает "из коробки". |
| Fuzzy-сопоставление команд       | `rapidfuzz`                   | Быстрый C++-бэкенд, устойчив к перестановке слов/мелким ошибкам распознавания. |
| Запуск процессов / URI           | `subprocess`, `os.startfile`  | Штатные средства ОС; `steam://rungameid/570` открывается через ассоциированный обработчик. |
| Ожидание готовности окна/процесса| `psutil` + `pywin32` (`win32gui`)| Не бьём кликами вслепую — ждём появления процесса/окна с таймаутом. |
| Клики/клавиатура                 | `pyautogui`                   | Простой API для click/hotkey, встроенный fail-safe (мышь в угол = стоп). |
| Поиск элементов Panorama UI      | `OpenCV` (`matchTemplate`) + `mss` | Надёжнее фиксированных координат при небольших расхождениях рендеринга; `mss` — быстрый захват экрана. |
| Конфиги                          | `PyYAML`                      | Человекочитаемые `config.yaml` / `commands.yaml`, легко редактировать без кода. |
| Обратная связь                   | `pyttsx3` (офлайн TTS) + `winsound` | Голосовое подтверждение и звуковой сигнал без облачных TTS. |
| Трей + хоткей                    | `pystray` + `keyboard`        | Иконка в трее с меню вкл/выкл, глобальный хоткей на случай, если постоянное прослушивание мешает. |

## 2. Архитектура

```
main.py                         # точка входа
src/dota_voice/
    config.py                   # загрузка config.yaml + commands.yaml
    logging_setup.py            # ротация логов в файл + консоль
    speech.py                   # SpeechListener: Vosk + sounddevice, фоновый поток
    commands.py                 # CommandMatcher: fuzzy-сопоставление фразы -> команда+параметры
    actions.py                  # ActionExecutor: выполняет шаги команды (STEP_HANDLERS)
    vision.py                   # OpenCV template matching поверх экрана (mss)
    process_utils.py            # запуск процессов, ожидание процесса/окна (psutil/win32gui)
    notify.py                   # TTS-озвучка + beep
    tray.py                     # иконка в трее, меню, глобальный хоткей
    app.py                      # склейка всех модулей в приложение
tools/
    calibrate.py                # интерактивная калибровка шаблонов UI под скриншот
config/
    config.yaml                 # пути, тайминги, синонимы ролей, параметры vision
    commands.yaml               # "команда -> шаги" (описательно, без кода)
templates/                      # эталонные PNG-скриншоты элементов UI Dota 2 (создаются калибровкой)
logs/                           # app.log (ротация)
```

Поток данных:

```
Микрофон --> SpeechListener (Vosk) --> текст
   текст --> CommandMatcher (rapidfuzz + roles) --> (command, params) | None
   (command, params) --> ActionExecutor.run_steps(steps, params)
        каждый шаг --> process_utils / vision+pyautogui / webbrowser / notify
```

Расширение: чтобы добавить новую команду, редактируется только
`config/commands.yaml` (новый список `phrases` + `steps`) — ядро
(`actions.py`, `commands.py`) трогать не нужно, если используются уже
существующие типы шагов. Новый **тип** шага добавляется одной записью в
словарь `self._handlers` в `ActionExecutor`.

## 3. Пример конфигов

Полные файлы: [config/config.yaml](config/config.yaml), [config/commands.yaml](config/commands.yaml).

Ключевые фрагменты — синонимы ролей:

```yaml
roles:
  mid:
    label: "Мидер"
    synonyms: ["мидер", "мид", "миддер", "middle", "вторая позиция", "2 позиция"]
```

Шаги команды (пример "рейтинговая игра"):

```yaml
- id: ranked_role
  phrases:
    - "начни рейтинговую игру на {role}"
    - "запусти рейтинг на {role}"
  role_param: role
  steps:
    - type: click_template
      template: play_button
      retries_key: max_retries
    - type: click_template
      template: ranked_roles_tab
    - type: select_exclusive_role   # сначала снимает ранее выбранную роль
      retries_key: max_retries
    - type: click_template
      template: find_match_button
```

## 4. План реализации (MVP)

**Этап 1 — "Базовый минимум" (без распознавания изображений):**
1. `process_utils.py` — запуск exe + ожидание процесса/окна. ✅
2. `speech.py` + `commands.py` — распознавание и fuzzy-матчинг фразы "базовый минимум". ✅
3. `actions.py` — шаги `launch_process`, `launch_uri`, `open_url_in_chrome`, `sleep`, `notify`. ✅
4. `tray.py` — иконка в трее и хоткей вкл/выкл. ✅

Этот этап уже полностью рабочий MVP — можно тестировать без Dota 2 запущенной
на экране.

**Этап 2 — рейтинговая игра через Panorama UI (сложнее):**
1. `vision.py` — template matching поверх `mss`-скриншота. ✅
2. `tools/calibrate.py` — интерактивная калибровка шаблонов (обвести мышью область). ✅
3. Добавить в `actions.py` шаг `click_template` с ретраями и fallback на
   `click_point`. ✅
4. Пользователь калибрует 5 шаблонов (см. раздел 6 ниже) под своё разрешение.
5. Тестировать пошагово: сначала `play_button` в одиночной команде, затем
   всю цепочку целиком.

Всё это уже реализовано в репозитории (см. дерево файлов выше) — это готовый
код MVP, а не псевдокод.

## 5. Установка и запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

> **Если `pip install` падает с `ERROR: Failed to build 'PyYAML'` (или любым
> другим пакетом) "when getting requirements to build wheel"** — это значит,
> что для твоей версии Python ещё нет готового wheel-файла под жёстко
> зафиксированную версию из `requirements.txt`, и pip пытается собрать пакет
> из исходников (а для этого на Windows обычно не установлен C-компилятор).
> В `requirements.txt` версии указаны как нижняя граница (`>=`), а не точный
> пин, так что обычно достаточно обновить pip и повторить установку:
> ```bash
> python -m pip install --upgrade pip
> pip install -r requirements.txt
> ```
> Если конкретный пакет всё равно не собирается — попробуй поставить его
> отдельно без версии (`pip install PyYAML`), чтобы pip сам выбрал последнюю
> версию с готовым wheel-файлом под твой Python.

Скачать офлайн-модель распознавания речи (Vosk, русский):
1. Перейти на https://alphacephei.com/vosk/models
2. Скачать `vosk-model-small-ru-0.22` (быстрая, ~45 МБ) или `vosk-model-ru-0.42` (точнее, ~1.8 ГБ)
3. Распаковать так, чтобы получилось `models/vosk-model-small-ru-0.22/...` в корне проекта
   (или указать другой путь в `config/config.yaml -> speech.model_path`)

Проверить и поправить под себя `config/config.yaml`:
- `apps.steam.path`, `apps.chrome.path`, `apps.discord.path` — реальные пути установки на твоей машине;
- `dota2.app_id` — обычно `570`, менять не нужно;
- `vision.calibrated_resolution` — разрешение экрана, под которое откалиброваны
  шаблоны UI. Проверить/обновить его отдельной командой, не запуская всё
  приложение:

  ```bash
  python tools/calibrate.py --check-resolution
  ```

  Она сравнит текущее разрешение экрана с записанным в конфиге и, если они
  разошлись (или значение ещё не задано), сама обновит `config.yaml`. При
  каждом запуске `main.py` та же проверка выполняется автоматически — если
  экран не совпадает с калибровкой, в лог (`logs/app.log`) и консоль
  выводится предупреждение до того, как ты успеешь наткнуться на "элемент UI
  не найден" при попытке начать игру.

Запуск:

```bash
python main.py
```

Появится иконка в трее (зелёная точка = прослушивание активно). Хоткей
`Ctrl+Alt+L` (настраивается в `config.yaml -> hotkeys.toggle_listening`)
временно включает/выключает распознавание команд, не убивая аудиопоток.

> Глобальный хоткей через библиотеку `keyboard` на Windows иногда требует
> запуска терминала от имени администратора — если хоткей не срабатывает,
> попробуй запустить `python main.py` в PowerShell "Запуск от имени администратора".

## 6. Калибровка шаблонов Dota 2 под своё разрешение

Команда "Начни рейтинговую игру на ..." использует 13 шаблонов. Их нужно
откалибровать один раз (и заново — при смене разрешения экрана или масштаба
интерфейса в настройках Dota 2). Перед первой калибровкой стоит проверить
текущее разрешение (см. раздел 5 выше):

```bash
python tools/calibrate.py --check-resolution
```

Список шаблонов:

| Имя шаблона                  | Что сфотографировать                                        |
|--------------------------------|--------------------------------------------------------------|
| `play_button`                  | Кнопка "Играть" в главном меню Dota 2                        |
| `ranked_roles_tab`             | Вкладка "Рейтинговый матч с ролями" на экране выбора режима  |
| `role_carry`                   | Иконка позиции 1 (Керри), **невыбранное** состояние          |
| `role_carry_selected`          | Иконка позиции 1 (Керри), **выбранное/подсвеченное**         |
| `role_mid`                     | Иконка позиции 2 (Мидер), невыбранное состояние              |
| `role_mid_selected`            | Иконка позиции 2 (Мидер), выбранное состояние                |
| `role_offlane`                 | Иконка позиции 3 (Оффлейнер), невыбранное состояние          |
| `role_offlane_selected`        | Иконка позиции 3 (Оффлейнер), выбранное состояние            |
| `role_support`                 | Иконка позиции 4 (Поддержка), невыбранное состояние          |
| `role_support_selected`        | Иконка позиции 4 (Поддержка), выбранное состояние            |
| `role_hard_support`            | Иконка позиции 5 (Полная поддержка), невыбранное состояние   |
| `role_hard_support_selected`   | Иконка позиции 5 (Полная поддержка), выбранное состояние     |
| `find_match_button`            | Кнопка подтверждения поиска матча                            |

**Зачем два состояния на роль:** иконки ролей в Dota — это переключатели, а
не эксклюзивный выбор: клик по одной иконке не снимает выбор с другой,
оставшейся с прошлой игры. Чтобы это исправить, шаг `select_exclusive_role`
(см. `config/commands.yaml`) сначала проверяет шаблон `_selected` для каждой
роли; те роли, что оказались выбраны, но не были названы голосом, кликаются
ещё раз, чтобы снять выбор, и только после этого кликается нужная роль (если
она ещё не выбрана). Чтобы отличить "выбрано" от "не выбрано" на экране,
нужны оба шаблона на каждую роль.

Порядок действий для каждого шаблона:

```bash
python tools/calibrate.py play_button
python tools/calibrate.py role_mid
python tools/calibrate.py role_mid_selected
```

1. Скрипт даёт 5 секунд — за это время нужно переключиться в окно Dota 2 и
   открыть нужный экран.
2. Для шаблона `_selected` — сначала кликни по иконке роли прямо в игре,
   чтобы она подсветилась/показала состояние "выбрано", и только потом
   запускай калибровку этого состояния — 5 секунд отсчёта как раз дают на
   это время до того, как будет сделан скриншот.
3. Делается полноэкранный скриншот, открывается окно с картинкой.
4. Обвести мышью (зажать ЛКМ и потянуть) прямоугольник вокруг элемента —
   чем плотнее рамка вокруг кнопки/иконки, без лишнего фона, тем надёжнее
   матчинг на разных фонах меню. Обводи невыбранное и выбранное состояние
   одной и той же роли одинаково (по тем же границам), чтобы отличалась
   только подсветка.
5. Отпустить кнопку мыши — файл сохранится в `templates/<имя>.png`, окно
   закроется само.

Повторить для всех 13 имён из таблицы. После этого можно тестировать команду:

```
"Начни рейтинговую игру на мидера"
```

...а затем сразу попробовать другую роль (например, "...на кэрри"), чтобы
убедиться, что предыдущая роль снимается, а не остаётся выбранной вместе с
новой.

Если элемент не находится (`vision.match_threshold` в `config.yaml`, по
умолчанию `0.86`) — в логе (`logs/app.log`) будет видно, для какого шаблона и
с каким score не прошёл матчинг. Варианты:
- перекалибровать шаблон точнее (без лишнего фона, ровно по границам элемента);
- слегка снизить `match_threshold` (например, до `0.8`);
- как крайний fallback — задать в `commands.yaml` для конкретного шага
  `fallback_point: [x, y]` с фиксированными координатами (поддерживается
  только обычным шагом `click_template`, не `select_exclusive_role`).

## 7. Выбор более приятного голоса TTS

По умолчанию ассистент говорит тем русским голосом SAPI5, который уже
установлен в Windows — обычно это "Microsoft Irina", который многим кажется
резким. Посмотреть, что реально установлено на твоей машине:

```bash
python tools/list_voices.py
```

Затем задать голос в `config/config.yaml`:

```yaml
feedback:
  tts_volume: 0.85     # 0.0-1.0, одно только снижение громкости заметно смягчает Irina
  tts_voice: "Zira"    # часть имени голоса из list_voices.py, без учёта регистра
```

`tts_voice: null` (по умолчанию) использует голос по умолчанию в Windows.
Если подстрока не совпала ни с одним установленным голосом — в лог пишется
предупреждение и используется голос по умолчанию, приложение не падает.

Если ни один установленный голос не нравится, в Windows 11 есть
дополнительные "естественные" голоса: **Параметры → Время и язык → Речь →
Управление голосами → Добавить голоса** — установи русский голос там сам
(это приложение не трогает системные настройки за тебя), затем запусти
`list_voices.py` заново. Если голос всё равно не появился в списке — скорее
всего, это новый голос на технологии "OneCore", который классические
SAPI5-приложения (как это) не видят без дополнительной ручной настройки
Windows; в этом случае проще пока остаться на подстроенном по громкости
голосе по умолчанию.

## Обработка нештатных ситуаций

- **Steam/Dota 2 уже открыты** — `process_utils.launch_process` проверяет
  `process_name` через `psutil` и не запускает второй экземпляр повторно.
- **Приложение не найдено по пути** — `ActionError` с понятным сообщением,
  голосовое уведомление "Не удалось выполнить шаг: ...", остановка
  последовательности (без попыток "угадать" дальше).
- **Шаблон UI не найден за N попыток** (`vision.max_retries`) — то же самое:
  остановка, лог, голосовое уведомление, никакой "долбёжки" кликами вслепую.

## Вне рамок задачи

Приложение не взаимодействует с игровым процессом после нажатия кнопки
поиска матча — никаких чтений памяти игры, аимботов или автоматизации
внутриигровых действий. Вся автоматизация ограничена меню до старта поиска.
